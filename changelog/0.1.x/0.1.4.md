# 0.1.4 — 2026-06-08

## Fixed

- **`get_alerts` timestamp comparison** — `issueDatetime` was stored as SWPC's space-separated format (`"2026-06-06 22:11:17"`) rather than ISO 8601; string comparison with an ISO cutoff silently dropped products dated on the cutoff day. Fix: `normalizeSwpcTime()` now applied in `getAlerts()` before storage; filter uses epoch comparison. Live feed: 2 → 6 results returned for a 48 h window (#6).
- **`get_kp_index` `forecast[]`** — the SWPC series embeds ~58 historical "observed" entries alongside the ~22 forward-looking ones; callers received mostly past Kp as "forecast." Fix: filter to `observed !== 'observed'` entries only. Also added `gScale`/`gLabel` fields to each forecast entry for G-scale consistency with `observed[]`; `format()` updated for format-parity (#7).
- **`get_aurora_forecast` sub-auroral verdict** — for latitudes below ~40° geographic (`minKpRequired === 9`), the `pct >= 5` branch emitted `"Low aurora chance — Kp≥9 needed"`, implying a sufficiently strong storm could produce aurora at equatorial latitudes. Fix: guard at top of verdict block returns a definitive "not visible at this latitude" message for `minKp === 9` before any pct-based branch fires (#9).
