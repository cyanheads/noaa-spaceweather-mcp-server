# 0.1.8 — 2026-06-30

## Changed

- **Dev dependencies** — `@biomejs/biome` ^2.5.0 → ^2.5.1, `@types/node` ^26.0.0 → ^26.0.1.

## Fixed

- **`get_alerts` `active_only`** now drops Warnings/Watches/Alerts whose parsed `validTo` has already elapsed; previously it filtered on product type plus the `max_age_hours` recency window only, so expired warnings (e.g. `K04W`/`K05W`) surfaced as active. Products with `validTo: null` (point-in-time Watch/Alert notices) or a `validTo` that `Date` cannot parse fall back to the recency window, so an active query never silently hides a warning with a missing or unreadable end time ([#12](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/12)).
- **`get_kp_index` `timeTag`** observed and forecast values now carry an explicit UTC designator (`…Z`). `normalizeSwpcTime()`'s early-return guard changed from `tag.includes('T')` to `tag.endsWith('Z')` — the T-separated, Z-less Kp feed shape (`2026-06-28T00:00:00`) previously short-circuited unchanged and read as local time — and both Kp call sites now run through it. Space-separated solar-wind and alert timestamps are byte-identical post-fix ([#13](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/13)).
- **`get_alerts` `messageCode`** — new output field carrying the full SWPC "Space Weather Message Code" parsed from the message body (e.g. `WARK04`, `ALTEF3`), the code that drives `productType`, `phenomenon`, and `level`. `productId` stays the short 4-char feed ID (e.g. `K04W`, `EF3A`); its schema description and the `SpaceWeatherAlert` JSDoc — which advertised full-code examples the field never returned — are corrected to the short-code shape. `format()` renders `messageCode (productId)` in the alert header ([#14](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/14)).
