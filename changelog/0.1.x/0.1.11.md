# 0.1.11 — 2026-07-16

## Added

- **`get_alerts` `noaaScale` field** — the NOAA scale a product's message body states (e.g. `"G1"`, `"R2"`), read from a `NOAA Scale:`/`Noaa Scale:` line or a Watch headline's `Category G<n>`; `null` when the body states none.
- **`get_alerts` `cancelled` field** — `true` when a record's headline reads `CANCEL WARNING:`/`CANCEL ALERT:`. Detection is per record, since the same `messageCode` can cycle between in-force and cancelled within minutes.

## Fixed

- **`get_alerts` `level` and `phenomenon`** now derive from the NOAA scale the message body states rather than the product code's numeric suffix and prefix shape, which misreported both for most live codes. `WATA30` (`WATCH: Geomagnetic Storm Category G2 Predicted`) previously returned `level: 30, phenomenon: "Aurora"` from the bare code and now returns `level: 2, phenomenon: "Geomagnetic"`; `ALTXMF` (`Noaa Scale: R2 - Moderate`) previously returned `level: 0` since its code carries no digits and now returns `level: 2`. Codes whose body states no scale — K-index warnings below the G-scale (`WARK04`, `ALTK04`) and codes whose suffix encodes something other than severity (`ALTEF3`, `ALTTP2`, `ALTTP4`, `SUM10R`) — report `level: 0`, meaning "no NOAA scale," not a severity of zero ([#18](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/18)).
- **`get_alerts` `active_only=true`** no longer returns cancellation notices as active. A cancellation carries the cancelled product's own `productType` (e.g. `Warning`, `Alert`) and no validity window, so neither the type filter nor the elapsed-`validTo` check excluded it; the filter now drops any record with `cancelled: true` ([#19](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/19)).
