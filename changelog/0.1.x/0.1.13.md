# 0.1.13 — 2026-09-16

## Changed

- **`sessionMode: 'stateless'` declared explicitly** in `createApp()` — with `MCP_SESSION_MODE` unset, the server now resolves `stateless` (previously the schema default `auto`, which resolves to `stateful`); an exported `MCP_SESSION_MODE` value still overrides it. The Docker image and `.env.example` already pinned `stateless`, so deployed HTTP behavior is unchanged.
- **Session mode published on the server card** — `/.well-known/mcp.json` carries it under `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode`.
- **Argument rejections now carry `structuredContent.error`** — an undeclared key, wrong type, or missing field returns `structuredContent.error` (code `-32602`, `Invalid arguments for tool …`) alongside the existing text result, `isError: true`.
- Server identity (name, version, description) resolves from the served package rather than the process working directory.
- SWPC 500/501 responses now classify as `ServiceUnavailable` rather than `InternalError`; a 500 retries, a 501 does not.
- An empty string or unsubstituted `${…}` placeholder in a framework `MCP_*` env var now reads as unset.
- `SIGTERM`/`SIGINT` exit the process explicitly — `0` once shutdown settles, `1` if the 10s ceiling fires.
- README restructured to an Overview section plus a per-tool capability reference; `.claude-plugin/plugin.json` gains `$schema`, author contact, and keywords; issue forms accept blank issues, link the private security-advisory form, and auto-assign `cyanheads`.
- Framework skill tree moved from `skills/` to `framework-skills/`, so installing this server's Claude Code or Codex plugin no longer auto-loads its development skills; paths updated across `CLAUDE.md`/`AGENTS.md`, `.mcpbignore`, `.github/CONTRIBUTING.md`, `docs/tree.md`. `## Publishing` section documents the straight-through release PR flow. 28 framework skills updated, `release-pr-review` added, `bun run audit:fix` script added.
