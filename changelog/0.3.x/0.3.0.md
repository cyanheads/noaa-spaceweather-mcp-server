# 0.3.0 — 2026-09-22

## Added

- **`get_solar_wind` `resolution: "summary"`:** empties `plasma`/`mag` and keeps every headline field, so the response stays near the headline size whatever the window instead of scaling with it. ([#38](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/38))
- **`get_solar_wind` window-extreme fields:** `speedMaxInWindow`/`speedMaxTimeTag`, `densityMaxInWindow`, `btMaxInWindow`, and `bzSouthMinutesInWindow` (1-minute records with Bz below 0; feed gaps not counted) — computed from the full pre-reduction window at every resolution, alongside the existing `bzMinInWindow`. ([#38](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/38))
- **`get_conditions` `yesterday`:** the R/S/G levels SWPC assessed for the previous UTC day, from the scales feed's key `"-1"`. Carries a date and no time — the key's `TimeStamp` is the feed's generation clock, not an observation time. Null when the feed carries no such key, or one missing a level. ([#34](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/34))
- **`get_solar_activity` per-region fields:** `cFlareCount`/`mFlareCount`/`xFlareCount` (same-day flare tallies SWPC attributed to the region), `areaMillionths`, and `firstObserved` on every `activeRegions[]` entry. A spotless region renders as "no spots (plage)" instead of an empty class. ([#39](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/39))

## Changed

- **Feed retry ladder bounded to one 45-second wall-clock budget** (`withRetry`'s `deadlineMs`), so a hung upstream now returns the classified `feed_unavailable` error before a 60-second client timeout instead of a bare transport timeout. A fast failure's attempt count and timing are unchanged. ([#41](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/41))
