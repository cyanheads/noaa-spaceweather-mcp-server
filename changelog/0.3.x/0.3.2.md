# 0.3.2 — 2026-10-08

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.14**: a numeric string sent for a number argument (`flare_hours: "48"`) or a boolean string for a boolean (`include_regions: "false"`) is repaired before validation, and `null` at an optional argument counts as absent (0.13.14); tool error results carry `data.requestId` and their text ends with `request <id>` (0.13.10); a result that breaks a tool's output schema fails as `-32603` instead of `-32007` (0.13.8)
- **Docker image**: production dependencies install in a separate `deps` stage on the build platform and musl-only packages are pruned (0.13.10, 0.13.11); Bun 1.4.0 → 1.4.2
- **`server.json`**: npm entries drop the `run start:*` package arguments and set `runtimeHint: "npx"`; the streamable-http entry fixes `MCP_TRANSPORT_TYPE` to `http` (0.13.11)
- Declared recovery hints now reach callers through the framework's recovery fill instead of per-throw forwards; the hints callers receive are unchanged
- README capability reference condensed, and `LOG_TOOL_FAILURE_PAYLOADS` documented

## Fixed

- **`noaa_spaceweather_get_solar_activity`** no longer fails the whole call when SWPC's 7-day flare feed carries a completed flare with no recorded peak: `recentFlares[].maxTime`, `maxClass`, `peakFluxWm2`, and `rScale` are now nullable (null when SWPC recorded no peak), and such a flare renders as "No recorded peak" ([#45](https://github.com/cyanheads/noaa-spaceweather-mcp-server/issues/45)). Calls that succeeded before return the same output
